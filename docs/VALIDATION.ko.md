# 실험 해석

[English](VALIDATION.md) · [한국어](VALIDATION.ko.md) · [简体中文](VALIDATION.zh-CN.md)

데모를 학습할 때 세 가지를 구분하세요.

1. **계획이 가능한가?** Dynamics·접촉 제약·충돌 여유를 확인하세요. Solver가 수렴했다는 사실만으로 충분하지 않습니다.
2. **로봇이 계획을 추종하는가?** 기준과 실제 움직임, 하중을 받는 접촉, 관절 및 토크 한계를 비교하세요. Reduced 모델에서 가능한 계획도 전신 로봇에서는 추종하기 어려울 수 있습니다.
3. **공정한 비교인가?** 설계 요소 하나를 비교할 때 환경·초기 상태·외란·제어기 설정을 고정하세요. 실패한 시도도 함께 살펴보세요.

모델 가정과 비교 실습은 각 Lab의 학습 노트를 참고하세요. 움직임이나 그래프를 자세히 분석할 때는 갤러리의 선택 항목에서 원시 데이터를 확인할 수 있습니다. README 명령으로 재현한 뒤 한 번에 하나씩 설정을 바꿔보세요.

## 데모의 가정

- Lab 1–2는 로봇팔 추종과 kinematics를 학습합니다. Lab 1의 정사각형 실습은 충돌을 비활성화하며, Lab 2의 frame 거리 휴리스틱은 mesh 충돌 검사가 아닙니다. Lab 3는 마찰이 작은 평판과 강체 probe를 사용합니다.
- Lab 4의 충돌 검사는 샘플링 기반입니다. 탐색 실패나 반복 예산 소진은 경로가 없다는 증명이 아닙니다. 반환한 경로와 실제 추종을 구분해 확인하세요.
- Lab 8은 reduced centroidal 모델 애니메이션입니다. Lab 9는 CoM·운동량·접촉력을 예측하며 관측기는 IMU 추정기가 아닙니다. Lab 10은 오프라인 전신 계획을 feedback으로 추종합니다.
- Lab 11–13은 평지와 시뮬레이터 상태를 사용합니다. Lab 13은 접촉 순서·시간을 고정하고 착지점을 조정합니다. 완주 여부와 함께 물리 제약을 비교하세요. 적응형 발 위치가 모든 지표를 개선하는 것은 아닙니다.

## 코드를 바꾼 뒤 확인하기

구현을 수정하면 해당 Lab의 테스트를 실행하세요. 전체 검사는 두 환경을 사용합니다.

```bash
.venv/bin/python -m pytest lab-*/tests tools/tests -q
.venv-ocp/bin/python -m pytest lab-10-whole-body-optimal-control/tests -q
```

주 환경에서 건너뛰는 Crocoddyl 검사는 두 번째 명령으로 실행합니다. 제어기를 바꿨다면 해당 Lab의 시뮬레이션 명령으로 실제 움직임도 확인하세요. 실행 시간은 컴퓨터 부하에 따라 달라지며 hard real-time 보장을 뜻하지 않습니다.
